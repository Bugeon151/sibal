# 데이터·입력 명세

> 상위 문서: [PRD](./PRD.md)
> 원칙: 서비스 안에서는 생성형 AI·LLM·ML 모델을 쓰지 않는다. 운영 서버도 두지 않는다. 모든 처리는 이 문서의 수식과 규칙으로 학생 기기의 브라우저 안에서 처리 엔진 코드가 한다. 키가 필요한 API만 키 중계 함수를 거친다.

## 입력 명세

학생이 직접 넣는 것은 화면 4곳이다. 필수는 주제와 모드 둘뿐이고, 나머지는 기본값이 있다. 태블릿 수업 중 사용을 고려해 타이핑을 최소화한다.

| 화면 | 필드 | 형식 | 필수 | 제한·검증 | 기본값 |
| --- | --- | --- | --- | --- | --- |
| 시작 | 모드 | 두 버튼: AI 허용 / 검색만 | 예 | 둘 중 하나, 결과 화면에서도 바꿀 수 있음 | 없음 (매번 선택) |
| 시작 | 탐구 주제 | 자유 텍스트 1줄 | 예 | 2~200자, 한글·영문 모두 허용 | 없음 |
| 시작 | 과목 | 드롭다운: 국어, 영어, 사회, 과학, 정보, 기타 | 아니오 | 질문 템플릿과 단서어 사전 선택에 사용 | 기타 |
| 시작 | 검색 범위 | 토글: 국내 논문 / 해외 논문 / 뉴스 | 아니오 | 최소 1개 켜짐 | 모두 켜짐 |
| 시작 | 최근 자료만 | 드롭다운: 전체 / 10년 / 5년 | 아니오 | 논문 발행 연도 필터 (뉴스는 항상 최신순) | 10년 |
| 탐구 질문 | 질문 선택 | 후보 1~3개 중 탭 + 직접 수정 칸 | 예 | 수정 시 5~200자 | 첫 번째 후보 |
| 탐구 질문 | 키워드 확인 | 추출된 키워드 태그, 삭제·추가 가능 | 예 | 1~5개, 각 1~40자 | 규칙 기반 추출 결과 |
| 탐구 질문 | 영문 키워드 | 태그 입력 | 아니오 | 0~5개, 각 1~40자. 비우면 KCI 영문 키워드로 자동 채움 | 없음 |
| 내 문장 검사 (F6) | 학생 문장 | 여러 줄 텍스트 (붙여넣기) | 예 | 최대 1,500자, 문장 분리 후 최대 10문장만 검사 | 없음 |
| AI 사용 내역 (F8, AI 허용만) | 사용한 외부 AI | 다중 선택: ChatGPT, Gemini, Claude, 뤼튼, 기타(직접 입력) | 예 | 최소 1개 | 없음 |
| AI 사용 내역 (F8, AI 허용만) | 추가 프롬프트 | 여러 줄 텍스트, 여러 개 추가 가능 | 아니오 | 각 최대 3,000자 | 없음 (패키지 프롬프트는 자동 포함) |
| AI 사용 내역 (F8, AI 허용만) | 활용 범위 | 체크박스: 자료 수집, 개념 이해, 구성 점검, 문장 피드백, 기타 | 예 | 최소 1개 | 자료 수집 |

- **학생이 입력하지 않는 것:** 이름, 학교, 학년, 연락처. P0에서는 로그인도 없다.
- **입력 정리:** 앞뒤 공백 제거, 연속 공백 1개로, 제어 문자 제거. 길이 초과는 잘라내지 않고 입력 칸에서 막는다.

## 외부 API에서 받는 정보

데이터를 받는 외부 호출은 이 세 곳뿐이다. 그 외의 외부 호출(특히 AI·번역 API)은 없다.

| 소스 | 호출 경로 | 이유 |
| --- | --- | --- |
| OpenAlex | 브라우저 → OpenAlex 직접 (키 없음). 한도(429·403)·네트워크 오류면 중계 함수로 재시도 | CORS 허용(`*`, 2026-11-08 확인). 키 없이는 **사용자 IP마다** 하루 약 100회라, 무료 공개로 사용자가 늘어도 각자 한도를 쓴다. 학교처럼 IP를 공유해 막히면 중계의 무료 키($1/일 ≈ 1,000회, 전체 공유)로 넘어간다. 직접 호출에는 사용자 정의 헤더를 넣지 않는다(CORS 사전 요청 실패) |
| KCI | 브라우저 → 중계 함수 → KCI | 키가 URL에 들어가 노출되므로 |
| 네이버 뉴스 | 브라우저 → 중계 함수 → 네이버 | Client Secret 헤더 노출 방지, 브라우저 직접 호출 불가 |

### OpenAlex (해외 논문) — 공식 문서로 확정

- **요청:** `GET /works?search=<영문 키워드>&filter=publication_year:><연도>&per_page=25&select=<아래 필드>`
- **키:** 없어도 호출은 되지만 무료 키를 받는다. 키 없이 초당 10회, 무료 키는 초당 30회이고, 무료 계정은 하루 사용 예산($1)이 있다. ([문서](https://help.openalex.org/how-to-use-the-api/rate-limits-and-authentication))

| 받는 필드 | 타입 | 우리가 쓰는 곳 |
| --- | --- | --- |
| `id` | 문자열 (W…) | 내부 원본 ID |
| `doi` | 문자열 | 중복 제거, 링크, 가짜 서지 대조 |
| `title` | 문자열 또는 null | 카드 제목. null이면 버림 |
| `publication_year` | 정수 | 연도 필터, 점수 |
| `language` | ISO 639-1 | 문장 분리기·토크나이저 선택 |
| `type` | 문자열 | `article`·`review` 우선, `paratext` 등 제외 |
| `authorships` | 목록 | 저자명 (최대 3명 + "외") |
| `primary_location.source` | 객체 | 학술지명 |
| `cited_by_count` | 정수 | 품질 점수 |
| `abstract_inverted_index` | 단어→위치 맵 | 초록 복원. 평문 초록은 제공되지 않음 |
| `open_access.is_oa`, `open_access.oa_url` | 불리언, 문자열 | 원문 링크, 점수 |

### KCI Open API (국내 논문) — 요청 형식 확인, 요소 이름 일부는 키 발급 후 확정

- **요청:** `GET https://open.kci.go.kr/po/openapi/openApiSearch.kci?apiCode=articleSearch&key=…&title=…`, XML 응답만 제공. 응답 루트는 `MetaData > outputData`, 논문은 `record`(여러 개), 전체 건수는 `result.total` (오픈소스 래퍼 코드로 확인, 2026-11-08)
- **검색어:** `title`이 필수 검색어다. 키워드를 모두 넣어 0건이면 핵심 키워드 2개로 한 번 더 검색한다.
- **검색 파라미터 (래퍼 기준):** `title`(필수), `keyword`, `abstract`, `author`, `journal`, `doi`, `dateFrom`·`dateTo`(YYYYMM), `sortNm`·`sortDir`, `displayCount`(최대 100), `page`
- **키 발급:** KCI에서 신청서 작성 후 한국연구재단에 공문을 보내는 방식으로 알려져 있어, 며칠 걸릴 수 있다.
- **알려진 함정:** `displayCount`와 상관없이 10건만 오는 경우가 있고, 전체 건수는 `total`에 있다. 필요하면 `page`를 돌려 받는다.
- **상세 조회:** `apiCode=articleDetail` + 논문 제어번호(예: ART002358582). 검색 결과에 초록이나 영문 키워드가 없을 때만 호출

| 받아야 하는 정보 | 우리가 쓰는 곳 | XML 요소 이름 |
| --- | --- | --- |
| 논문 제어번호 (article-id) | 내부 원본 ID, 상세 조회 | 확인 필요 |
| 제목 (한·영) | 카드 제목, 중복 제거 | 확인 필요 |
| 저자 | 서지 | 확인 필요 |
| 초록 (한·영) | 요약과 근거 문장 | 확인 필요 |
| 저자 키워드 (한·영) | 영문 검색어, 한·영 대응 사전 | 확인 필요 |
| 발행 연도 | 필터, 점수 | 확인 필요 |
| 학술지명 | 서지 | 확인 필요 |
| DOI | 중복 제거, 링크 | 확인 필요 |
| 피인용 수 | 품질 점수 | 확인 필요 |
| 원문 공개 여부, KCI 상세 URL | 원문 링크 | 확인 필요 |
| 연구분야 | 과목 가중치 | 확인 필요 |

### 네이버 검색 API (뉴스) — 공식 문서로 확인

- **제공:** NAVER API HUB. 현재 한시적 무료이고 유료 전환 시 사전 공지 예정. 네이버 검색 카테고리 합산 월 최대 775,000건, 키당 50 RPS. ([문서](https://guide.ncloud-docs.com/docs/apihub-overview))
- **요청:** `GET https://naverapihub.apigw.ntruss.com/search/v1/news?query=…&display=20&sort=sim`, 헤더 `X-NCP-APIGW-API-KEY-ID`(Client ID), `X-NCP-APIGW-API-KEY`(Client Secret). 최신성은 점수 공식으로 반영 ([문서](https://api.ncloud-docs.com/docs/naver-api-hub-search-news))
- **받는 정보:** `items[]`의 `title`, `originallink`, `link`, `description`(요약문 2~3줄), `pubDate`. 본문은 제공되지 않는다.
- **정리:** 제목·요약문의 HTML 태그(`<b>` 등)와 엔티티 제거, 언론사명은 원문 링크 도메인으로 매핑
- **교체 가능 구조:** 뉴스 소스는 어댑터 하나로 분리해, 유료 전환 시 다른 소스로 바꿔 끼운다.

출처: [OpenAlex Work 객체](https://help.openalex.org/api-entities/works/work-object), [KCI MCP 서버 (래퍼)](https://glama.ai/mcp/servers/avt3ked1j6), [NAVER API HUB 개요](https://guide.ncloud-docs.com/docs/apihub-overview)

## 공통 데이터 모델

화면과 처리 엔진은 아래 타입만 주고받는다. 외부 API의 원본 필드는 엔진 밖으로 나가지 않는다. 화면에 나오는 모든 문장은 검색 결과의 원문 문장이거나 고정 템플릿 문구다.

```ts
type Mode = 'ai' | 'search_only'

type Sentence = { id: string; text: string }  // id = 'P2-S3' (논문) 또는 'N1-S1' (뉴스)

type Paper = {
  id: string              // 'P1'..'P5' — 이번 리서치 안에서만 쓰는 짧은 ID
  source: 'kci' | 'openalex'
  sourceId: string        // KCI 제어번호 또는 OpenAlex W…
  doi: string | null
  title: string
  authors: string[]       // 최대 3명, 나머지는 etAl=true
  etAl: boolean
  journal: string | null
  year: number
  language: 'ko' | 'en' | 'other'
  citedBy: number | null
  isOa: boolean
  url: string             // OA 원문 또는 상세 페이지
  score: number           // 0~100
  selectReasons: string[] // 예: '피인용 상위', '최근 5년', '원문 공개'
  sentences: Sentence[]   // 초록을 문장 단위로 나눈 것
  keySentences: { sentenceId: string; role: 'purpose' | 'method' | 'result' | 'conclusion' | null }[]  // F4, 최대 3개
  definitions: { term: string; sentenceId: string }[]  // "~란 ~이다" 형태의 정의 문장
}

type News = {
  id: string              // 'N1'..'N5'
  title: string
  press: string | null    // 원문 링크 도메인으로 매핑
  publishedAt: string     // ISO 일시
  url: string             // 원문 링크
  sentences: Sentence[]   // 요약문을 문장 단위로 나눈 것
  score: number
}

type Direction = 'increase' | 'decrease' | 'no_effect' | 'conditional' | 'none'

type Comparison = {
  concepts: {
    concept: string                // 예: '수면 시간'
    agreement: 'agree' | 'conflict' | 'mixed' | 'single'  // 단서어 판정 결과
    cells: { paperId: string; direction: Direction; evidence: string[] }[]
  }[]
}

type Verdict = 'supported' | 'partial' | 'unsupported'

type CheckResult = {
  sentence: string        // 학생이 쓴 문장 원문
  verdict: Verdict
  evidence: string[]      // Sentence.id, 비면 '근거 없음'
  reasonCode: 'match' | 'low_overlap' | 'direction_conflict' | 'number_mismatch' | 'scope_mismatch' | 'group_mismatch' | 'no_evidence'
  reason: string          // reasonCode별 고정 문구
  crossLanguage: boolean  // 근거가 영어 문장이라 직접 확인이 필요
  newsReference: string[] // 뉴스에서 찾은 참고 문장 ID (판정에는 쓰지 않음)
  scores: { coverage: number; bm25: number }  // 디버깅·임계값 조정용
  suggestPaperIds: string[]  // 미지지일 때 보완할 후보 논문 ID ('C1'…), checkSentences 반환의 candidates에 서지가 있음
}

type Disclosure = {
  serviceUsesAi: false    // 이 서비스는 AI를 쓰지 않았음을 명시
  tools: string[]         // 학생이 쓴 외부 AI
  prompts: { label: string; text: string }[]  // 패키지 원문 + 학생 추가분
  scope: string[]
  usedAt: string          // ISO 일시
  papers: string[]        // 참고문헌 문자열
}
```

- **문장 ID 규칙:** `자료ID-S번호`. 모든 `evidence` 값은 해당 리서치의 `sentences`에 있어야 한다.
- **화면 표시 규칙:** `evidence`가 비면 "근거 없음"으로 표시한다. 화면 코드는 문장을 만들거나 고치지 않는다.

## 구조와 인터페이스

운영 서버는 없다. 정적 웹앱 하나 안에 화면과 처리 엔진이 들어 있고, 키 중계 함수만 따로 배포한다.

```
[학생 태블릿 브라우저]
  화면 (UI) ──함수 호출──▶ 처리 엔진 (Web Worker)
                              │  규칙 토크나이저, 단서어·동의어·한영 사전(정적 파일)
                              ├──▶ OpenAlex (직접)
                              └──▶ 키 중계 함수 ──▶ KCI, 네이버 뉴스
```

### 처리 엔진 인터페이스

화면은 아래 함수만 부른다. 모두 비동기이고, 무거운 계산은 Web Worker 안에서 돈다.

| # | 함수 | 기능 | 모드 | 입력 | 반환 |
| --- | --- | --- | --- | --- | --- |
| 1 | `suggestQuestions` | F1 | 둘 다 | `{ topic, subject? }` | `{ questions: {id, text}[], keywords: string[] }` |
| 2 | `runResearch` | F2~F5 | 둘 다 | `{ mode, topic, question, keywords, keywordsEn?, sources: {kci, openalex, news}, years: 0\|5\|10 }` | `{ researchId, mode, papers: Paper[], news: News[], comparison: Comparison, keywordsEn, sourceStatus: {kci, openalex, news}, cached }` |
| 3 | `checkSentences` | F6 | 둘 다 | `{ researchId, text }` | `{ results: CheckResult[], truncated, candidates: CandidatePaper[] }` |
| 4 | `buildPackage` | F7 | AI 허용만 | `{ researchId }` | `{ text, promptId }` |
| 5 | `buildDisclosure` | F8 | AI 허용만 | `{ researchId, tools, extraPrompts, scope }` | `{ disclosure: Disclosure, text }` |
| 6 | `buildReferences` | F10 (P1) | 둘 다 | `{ researchId, style: 'apa' }` | `{ items: string[] }` |

- **`sourceStatus`:** 소스별 `'ok' | 'failed' | 'skipped'`. 하나가 `failed`여도 나머지 결과를 돌려주고, 화면은 "국내 논문 검색이 잠시 안 됩니다" 같은 안내를 띄운다.
- **리서치 상태:** 엔진은 `researchId`로 논문·뉴스·문장·후보 목록을 기기 안(IndexedDB)에 24시간 보관한다. 3~6번은 이 상태를 읽는다.
- **사용 내역의 프롬프트 원문:** 4번에서 만든 패키지를 엔진이 `promptId`로 기억하고, 5번에서 자동으로 포함한다.
- **모드 검사:** 화면에서 탭을 숨기는 것과 별개로, 엔진도 검색만 리서치의 4·5번 호출을 거부한다.

**오류 형식:** 엔진은 `EngineError { code, message }`를 던진다. `message`는 학생에게 그대로 보여줄 수 있는 한국어다.

| code | 언제 |
| --- | --- |
| `INVALID_INPUT` | 입력 명세의 길이·개수 위반 |
| `MODE_FORBIDDEN` | 검색만 리서치에 4·5번 호출 |
| `NO_RESULTS` | 모든 소스 0건. 화면은 키워드 수정을 안내 |
| `EXPIRED` | `researchId` 상태가 만료되었거나 지워짐 |
| `RATE_LIMITED` | 중계 함수가 429를 돌려줌 |
| `SOURCES_DOWN` | 모든 소스 실패하고 기기 캐시도 없음 |
| `OFFLINE` | 네트워크 없음. 캐시된 리서치만 열람 가능 |

### 키 중계 함수

계산·저장·판단을 하지 않고, 정해진 요청에 키를 붙여 전달만 한다.

| 경로 | 받는 파라미터 | 하는 일 |
| --- | --- | --- |
| `GET /openalex` | `q`, `fromYear`, `perPage` | OpenAlex `/works`에 select·기간 필터·키를 붙여 호출, JSON 그대로 반환 |
| `GET /kci/search` | `q`, `page`, `dateFrom`, `dateTo` | KCI `articleSearch`에 키를 붙여 호출, XML 그대로 반환 |
| `GET /kci/detail` | `id` | KCI `articleDetail` 호출, XML 그대로 반환 |
| `GET /news` | `q`, `display` | 네이버 뉴스 검색에 Client ID·Secret 헤더를 붙여 호출, JSON 그대로 반환 |

- **허용 목록:** 위 경로와 파라미터만 통과시키고, 나머지는 400.
- **남용 방지:** 우리 도메인에서 온 요청만 허용(Origin 검사), 기기 ID(`X-Device-Id` 헤더, 화면이 localStorage에 만들어 엔진에 전달)별 분당 호출 제한(기본 30회).
- **엣지 캐시:** 같은 요청(경로 + 정렬한 파라미터)의 정상 응답을 Cloudflare 캐시에 보관한다. KCI·OpenAlex 검색 24시간, KCI 상세 7일, 뉴스 1시간. 캐시 키에는 키·기기 ID·출처가 들어가지 않고, 오류 응답은 보관하지 않는다. 캐시 적중은 호출 제한에 세지 않는다. 여러 학생이 같은 주제를 검색해도 외부 API는 한 번만 불러서, 우리 키 하나로 전체가 나눠 쓰는 KCI·네이버 한도를 아낀다.
- **로그:** 시각, 경로, 응답 코드만. 검색어는 남기지 않는다.
- **키 보관:** 플랫폼의 비밀 변수에만 둔다. 코드 저장소에는 넣지 않는다.

## 처리 엔진 규칙과 수식

모든 숫자(가중치, 임계값)는 초기값이다. 1주차에 만드는 판정 세트로 조정하고, 설정 파일로 빼서 코드 수정 없이 바꿀 수 있게 한다.

### 공통: 텍스트 전처리

- **한국어 토큰:** 자체 규칙 토크나이저로 어절에서 조사(긴 것부터)와 서술어 어미(하였다·된다·적인 등)를 떼어 내용어만 남긴다. 조사처럼 보이는 글자로 끝나는 명사(전문가, 차이, 효과 등)는 예외 사전으로 지킨다. 숫자는 단위와 함께 남긴다.
- **형태소 분석기를 쓰지 않는 이유 (2026-11-08 확인):** 브라우저용 Kiwi(0.24)의 기본 모델은 신경망 언어모델(cong.mdl)뿐이라 AI 미사용 원칙과 맞지 않고, 모델 파일이 약 110MB라 학교 태블릿에 무겁다.
- **영어 토큰:** 소문자화, 불용어 제거, Porter 어간 추출
- **불용어:** "연구", "분석", "결과", "본", "대한" 같은 논문 상투어는 키워드·유사도에서 제외
- **문장 분리:** 한국어는 `다.`·`요.`·`음.` 등 종결 기준, 영어는 마침표·물음표 기준. `et al.`, `e.g.`, `i.e.`, 소수점, 약어는 예외. 10자 미만 조각은 앞 문장에 붙인다.
- **동의어·한영 대응 사전:** 두 가지로 만든다.
    1. 손으로 만든 교과 주제 동의어 사전 (예: 스마트폰 = 휴대전화)
    2. KCI 논문의 한·영 저자 키워드 쌍에서 자동 수집한 대응 (예: 수면 ↔ sleep). 같은 위치의 키워드 쌍이 3회 이상 나오면 등록
    - 두 사전 모두 개발 단계에서 스크립트로 만든 정적 JSON 파일로 앱에 포함한다. 사용 중에 수집하거나 서버에 쌓지 않고, 사전 갱신은 앱 배포로 한다.

### F1 키워드와 탐구 질문

1. 주제에서 명사(NNG, NNP)를 뽑고 불용어를 뺀다. 나온 순서를 유지하고 최대 5개.
2. 주제 문장의 패턴을 정규식으로 찾는다.
    - "A이/가 B에 미치는 영향" → 원인 A, 결과 B
    - "A와/과 B" → 관계형
    - 그 외 → 단일 주제형
3. 패턴에 맞는 질문 템플릿을 채운다. 조사는 앞 단어의 받침 유무로 고른다 (마지막 글자 코드 `(c - 0xAC00) % 28 ≠ 0`이면 받침 있음 → 은/이/과/을).
    - 영향형: "{A}{은/는} {B}에 어떤 영향을 미치는가?", "{A}{와/과} {B}의 관계는 어떠한가?", "{B}에 영향을 주는 {A} 외의 요인은 무엇인가?"
    - 관계형: "{A}{와/과} {B}{은/는} 어떤 관계가 있는가?", "{A}{이/가} 높을수록 {B}{은/는} 어떻게 달라지는가?"
    - 단일형: "{A}의 현황은 어떠한가?", "{A}의 원인은 무엇인가?", "{A} 문제를 줄이는 방안은 무엇인가?"
4. **영문 키워드:** 한국어 키워드마다 사전의 대표 영어 1개를 먼저 넣고 남는 자리를 두 번째 표현으로 채운다(일반어 제외, 최대 5개). 사전에 없으면 한국어 키워드로 OpenAlex를 검색한다. 학생이 넣지 않았으면, KCI 상위 10편의 영문 저자 키워드를 빈도순으로 세어, 한국어 키워드와 대응되는 것을 우선으로 최대 5개 고른다.

### F3 선별 점수

**논문 (0~100점)**

```latex
S_{paper} = 30 \cdot \frac{BM25(q, d)}{\max_{d'} BM25(q, d')} + 30 \cdot \frac{\ln(1 + c)}{\max_{d'} \ln(1 + c')} + 25 \cdot \max\left(0, 1 - \frac{Y_{now} - Y}{10}\right) + 15 \cdot OA
```

- `q`: 키워드, `d`: 제목+초록, `c`: 피인용 수, `Y`: 발행 연도, `OA`: 원문 공개면 1
- **주제 포함률 `T`:** 핵심 키워드(사용·이용 같은 일반어 제외) 중 제목·초록에 나오는 비율(동의어·영어 포함). 최종 점수는 `S_paper × (0.4 + 0.6·T)`. `T ≥ 0.66`인 논문이 3편 이상이면 `T ≤ 0.5`인 논문은 선별에서 뺀다(후보 풀에는 남김). 인용이 많아도 주제가 빠진 논문(예: 미세먼지·천식 주제에 미세먼지·피부 논문)이 뽑히지 않게 하기 위해서다 (2026-11-09, 실제 OpenAlex 검색으로 확인).
- BM25 파라미터 k1 = 1.2, b = 0.75. 정규화는 같은 검색의 후보 안에서 한다.
- 초록 문장이 2개 미만이면 점수와 상관없이 맨 뒤로 보낸다.
- 국내·해외를 모두 켜면, 결과가 있는 한 소스별 최소 1편씩 넣는다.
- 상위 3~5편: 70점 이상이 5편을 넘으면 5편, 아니면 최소 3편.

**뉴스 (0~100점)**

```latex
S_{news} = 60 \cdot \frac{BM25(q, d)}{\max_{d'} BM25(q, d')} + 40 \cdot 2^{-\Delta t / 30}
```

- `d`: 제목+요약문, `Δt`: 발행 후 지난 일수 (반감기 30일)
- 같은 사건 기사 중복 제거: 제목 토큰 자카드 유사도 0.6 이상이면 점수가 높은 것만 남긴다.
- 상위 3~5건.

### F4 핵심 문장 추출

논문마다 초록 문장 중 최대 3개를 골라 원래 순서대로 보여준다. 문장은 고치지 않는다.

```latex
S_{sent}(i) = 0.5 \cdot TR(i) + 0.3 \cdot \frac{BM25(q, s_i)}{\max_j BM25(q, s_j)} + 0.2 \cdot G(i)
```

- **TR(i):** TextRank 점수 (0~1 정규화). 문장 사이 가중치는 TF-IDF 코사인 유사도, 감쇠 계수 0.85, 30회 반복 또는 변화량 0.0001 미만에서 종료
- **G(i):** 구조 점수. 문장 역할이 있으면 역할 점수(결과 1.0, 결론 0.9, 목적 0.6, 방법 0.3, 배경 0.1), 없으면 위치 점수(첫 문장 0.5, 마지막 0.6, 나머지 0.3). 실제 초록에서 배경 문장이 핵심으로 뽑히는 문제가 있어 위치 점수에서 바꿨다 (2026-11-08)
- **역할 태그:** 구조화 초록 머리말("RESULTS:", "(3) Results:", "결과:" 등)이 있으면 그것을 먼저 쓰고, 없으면 단서어 규칙:
    - 목적: "본 연구는", "목적", "aim", "purpose"
    - 방법: "대상으로", "설문", "실험", "분석하였다", "method", "survey"
    - 결과: "나타났다", "유의", "증가", "감소", "found", "showed"
    - 결론: "시사", "제언", "필요하다", "suggest", "implication"
- **정의 문장:** "X란/X는 …을 의미한다/말한다/이다", "X is defined as" 패턴을 찾아 용어와 문장을 연결한다.

### F5 비교표

1. **개념 고르기:** 선별 논문 전체에서 내용어의 TF-IDF 합이 높은 순으로, 2편 이상에 나오는 것만 고른다. 동의어·영어는 사전 대표형으로 묶는다(휴대폰·smartphone → 스마트폰). 관계어(영향, 관계 …)와 방향어(증가, 감소 …)는 개념이 될 수 없다.
2. **칸 채우기:** 논문 × 개념마다 **연구 결과 문장**(목적·권고 문장 제외)에서 그 개념의 방향을 읽는다. 방향은 문장 전체가 아니라 **개념 바로 뒤 4어절**(영어는 앞 3단어 포함) 안의 단서어로 정한다.
    - 원인 쪽 단어가 결과 쪽 방향을 가져가지 않게 하기 위해서다. "최저임금 인상 이후 … 고용이 감소" → 고용은 감소, 최저임금은 방향 없음.
    - 개념과 방향어 사이에 목적어(~을/를)가 있으면 바뀌는 것은 그 목적어다. "사용은 수면의 질을 낮추는" → 질은 감소, 사용은 방향 없음.
    - "A할수록 B" 문장에서 개념이 조건 쪽(A)에만 있으면 방향을 주지 않는다.
3. **행 고르기:** 방향이 하나도 잡히지 않은 개념은 뺀다. 두 편 이상에서 방향이 잡힌 개념을 먼저, 최대 5개.

| 방향 | 한국어 단서어 (예) | 영어 단서어 (예) |
| --- | --- | --- |
| 증가 | 증가, 향상, 높아, 높였, 늘어, 올라, 긍정적, 정적 상관 | increase, improve, higher, positive |
| 감소 | 감소, 저하, 낮아, 낮추, 줄어, 떨어, 짧았, 부정적, 부적 상관 | decrease, reduce, lower, negative |
| 효과 없음 | 유의하지 않, 차이·관계·변화가 없 | no significant, not associated, remained the same |
| 조건부 | 경우에만, 때에만, 집단에서만, 따라 다르 | only when, depending on, among |

- **부정 처리:** 방향 단서어 뒤 5어절 안에 "않", "못", "없"이 있으면 증가↔감소를 뒤집는다. 단, "유의하지 않"은 "효과 없음"으로 먼저 처리한다.
- **여러 문장이면:** 다수결, 동률이면 "조건부"
- **행 판정:** 모두 같은 방향이면 `agree`. 증가와 감소가 같이 있거나, 증가·감소와 효과 없음이 같이 있으면 `conflict`. 그 외는 `mixed`, 방향이 잡힌 칸이 1개면 `single`.
- 모든 칸은 근거 문장을 함께 보여준다. 표는 판정이 아니라 "어느 문장을 비교해 보면 되는지" 안내하는 용도로 표시한다.
- **알려진 한계:** "수면 장애와 정적 상관"처럼 결과 변수의 극성이 반대인 문장은 방향이 뒤집혀 보일 수 있다. 근거 문장을 같이 보여주는 이유다.

### F6 내 문장 근거 검사

학생 문장마다 아래 순서로 계산한다. 대상은 선별 논문의 초록 문장이고, 뉴스 문장은 "참고"로만 표시하며 판정 근거로 쓰지 않는다.

1. **토큰 확장:** 학생 문장의 내용어 집합 `T(q)`(숫자 포함)를 동의어·한영 대응 사전으로 확장한다. "높아진다", "줄었다" 같은 방향어는 내용어에서 빼고 3단계에서 따로 본다.
2. **후보 찾기:** 모든 초록 문장 `s`에 대해 IDF 가중 포함률 `C`와 순위 점수 `R`을 계산한다. 근거 문장들에 드문 핵심어가 빠지면 `C`가 크게 깎인다.

```latex
C(q, s) = \frac{\sum_{t \in T(q),\ t \in T^{+}(s)} idf(t)}{\sum_{t \in T(q)} idf(t)}, \qquad idf(t) = \ln\left(1 + \frac{N - n_t + 0.5}{n_t + 0.5}\right), \qquad R(q, s) = 0.6 \cdot C + 0.4 \cdot \frac{BM25(q, s)}{\max_{s'} BM25(q, s')}
```

   `N`은 근거 문장 수, `n_t`는 `t`(동의어 포함)가 든 문장 수다. `R`이 가장 큰 문장을 `s*`로 잡되, 학생 문장에 방향이 있으면 포함률 차이 0.1 이내의 후보 중 방향이 있는 결과 문장을 우선한다. `C`가 0.5 이상인 두 번째 문장이 있으면 최대 2개까지 근거로 붙인다.

   - **근거 고르기 순서:** 포함률이 하한(0.35)을 넘는 후보 중 ① 학생 문장의 **핵심어**(근거 문장 4개 중 1개 이하에만 나오는 드문 단어, 예: 제조업·국어)를 많이 담은 문장 → ② 학생 문장에 방향이 있으면 방향이 있는 문장 → ③ `R` 순.
   - 방향어(감소, 개선 …)와 숫자는 포함률에서 뺀다. 방향은 3단계에서, 숫자는 4단계에서 따로 본다.
   - 근거 문장이 대조 연결어("~으나", "~지만", "반면", "~했고", but, whereas)로 나뉘면, 학생 문장의 주제어(예: 수학 vs 국어)가 있는 절만 본다.
3. **방향·효과 비교:** F5와 같은 단서어 규칙으로 방향을 정한다. "A할수록 B" 문장은 결과 쪽(B)만 본다. 한쪽만 부정적 결과(장애·문제·부족·위험, disturbance·risk)를 말하면 방향을 뒤집어 비교한다. 다음 경우가 충돌이다.
    - 증가 ↔ 감소
    - 효과 없음 ↔ 증가·감소
    - 효과 없음 ↔ 효과·차이가 있다는 주장 ("효과가 있었다", "더 효과적이다")
4. **수치 비교:** 학생 문장의 숫자(%, 배, 명 등 단위 포함)가 `s*`에 그대로 없으면 수치 불일치다.
   - 근거로 고른 문장이 목적·권고 문장인데, 비슷하게 강한(포함률 차 0.15 이내) **결과 문장**이 반대 방향이면 그 결과 문장을 근거로 미지지로 판정한다.
5. **집단 비교:** 학생 문장과 근거의 집단이 반대(남학생↔여학생, boys↔girls)이거나, "더 높다"고 한 집단이 반대면 미지지(`group_mismatch`).
6. **범위 비교:** 학생 문장에 전칭 표현(모든, 항상, 반드시 등)이 있는데 `s*`가 조건부(집단에서만, 경우에만 등)면 범위 확대다.
7. **판정 (위에서부터 먼저 맞는 규칙 적용):**

| 순서 | 조건 | 판정 | reasonCode |
| --- | --- | --- | --- |
| 1 | `C < 0.35` | 미지지 | `no_evidence` |
| 2 | 방향·효과 충돌 | 미지지 | `direction_conflict` |
| 3 | 집단 반대 | 미지지 | `group_mismatch` |
| 4 | 수치 불일치 (단위가 다르거나 근거가 영어면 숫자만 비교) | 부분 지지 | `number_mismatch` |
| 5 | 범위 확대 | 부분 지지 | `scope_mismatch` |
| 6 | `C ≥ 0.5`이고, 근거 어디에도 없는 명사형 토큰의 IDF 비중이 0.2 미만 | 지지 | `match` |
| 7 | 그 외 | 부분 지지 | `low_overlap` |

- **평가 결과 (2026-11-08):** 판정 세트는 모두 직접 작성한 가상 초록·문장이다(영어 주제만 실제 OpenAlex 초록).

| 세트 | 용도 | 문장 | 정확도 | 미지지 탐지 | 지지 정밀도 |
| --- | --- | --- | --- | --- | --- |
| tuning v0 | 규칙·임계값 조정 | 34 | 94.1% | 92.3% | 100% |
| holdout v0 | 처음엔 검증용, 오류를 보고 규칙을 고쳐 이후 개발용 | 33 | 87.9% (처음 75.8%) | 93.3% | 100% (처음 75.0%) |
| **holdout v1** | **규칙을 고친 뒤 새로 작성, 첫 실행 결과** | 28 | **60.7%** (한국어 72.7%, 영어 16.7%) | 71.4% | 83.3% (한국어 100%) |
| holdout v1 (이후) | v1 오류로 언어 규칙을 더 고친 뒤 | 28 | 67.9% (한국어 72.7%, 영어 50.0%) | 78.6% | 100% |

   **가장 믿을 만한 수치는 holdout v1 첫 실행이다.** 한국어 논문에서는 "아닌데 지지"가 없었고, 오류 대부분은 지지를 부분 지지로 낮게 본 경우(바꿔 쓰기·동의어)다. 영어 논문 근거 검사는 약하므로 `crossLanguage` 표시로 "직접 확인 필요"를 함께 보여준다. 다음 측정은 실제 학생 문장으로 한다.
- **임계값 근거 (2026-11-08, 판정 세트 v0 34문장):** 지지 기준 0.5에서 정확도 91.2%, 미지지 탐지 92.3%, 지지 정밀도 100%. 0.45로 낮추면 정확도 94.1%지만 지지 정밀도가 93.8%로 떨어져, "아닌데 지지"를 피하는 쪽을 택했다. 세트가 작아 과적합 위험이 있으므로 실제 문장으로 늘린 뒤 다시 조정한다 (`npm run eval:f6`).
- **교차 언어:** `s*`가 영어 문장이면 판정은 그대로 하되 `crossLanguage: true`를 붙여 "해외 논문 근거, 직접 확인 필요"를 함께 보여준다.
- **보완 논문 제안:** 미지지 문장은 리서치 상태에 보관한 후보 최대 20편 중 `BM25(q, 제목+초록)` 상위 2편을 제안한다. 새 검색은 하지 않는다.
- **이유 문구 (고정):**
    - `match`: "논문 문장과 내용이 일치해요."
    - `low_overlap`: "일부 내용만 논문에 있어요. 근거 문장을 확인해 보세요."
    - `direction_conflict`: "논문은 반대 방향의 결과를 말하고 있어요."
    - `number_mismatch`: "문장의 숫자가 논문에서 확인되지 않아요."
    - `scope_mismatch`: "논문은 일부 집단·조건에서만 확인된 결과예요. 범위를 좁혀 써 보세요."
    - `group_mismatch`: "논문은 다른 집단(예: 남학생과 여학생)의 결과를 말하고 있어요."
    - `no_evidence`: "선택한 논문에서 이 내용을 찾지 못했어요."

### F7 프롬프트 패키지와 F8 사용 내역

- 둘 다 고정 템플릿에 리서치 데이터(서지, 핵심 문장, DOI, 학생 질문)를 끼워 넣는다.
- 패키지 템플릿에는 "설명과 피드백만 하고 문장을 대신 써 주지 말 것" 제약이 고정으로 들어가고, 본문 작성 요청 문구는 템플릿 단위 테스트로 막는다.
- 사용 내역에는 "자료 검색 도구(본 서비스)는 AI를 사용하지 않음" 문구가 고정으로 들어간다.

## 저장과 개인정보

우리 쪽에는 저장소가 없다. 모든 데이터는 학생 기기 안에만 있고, 학생이 쓴 문장과 프롬프트는 기기 밖으로 나가지 않는다. 기기 밖으로 나가는 것은 검색어(외부 데이터 API로)뿐이다.

| 데이터 | 저장 위치 | 보관 기간 | 비고 |
| --- | --- | --- | --- |
| 검색 결과 (키워드·소스·연도 조합 별) | 기기 IndexedDB | 논문 7일, 뉴스 6시간 | 소스 장애·재검색 대비 |
| 리서치 상태 (자료, 문장, 후보, 패키지 원문) | 기기 IndexedDB | 24시간 | `researchId`로 접근 |
| 학생 문장 (F6) | 메모리에서만 처리 | 검사 후 즉시 폐기 | 네트워크 전송 없음 |
| 추가 프롬프트 (F8) | 메모리에서만 처리 | 사용 내역 생성 후 폐기 | 네트워크 전송 없음 |
| 사전 파일 (예외 명사, 단서어, 동의어, 한영) | 앱 캐시 (Service Worker) | 앱 버전 갱신 때까지 | 개인정보 아님 |
| 최근 리서치 목록 | 기기 localStorage | 사용자가 지울 때까지 | 학교 공용 태블릿을 고려해 "기록 지우기" 버튼 제공 (IndexedDB까지 함께 삭제) |
| 중계 함수 로그 | 중계 플랫폼 | 플랫폼 기본값 | 시각, 경로, 응답 코드만. 검색어 미기록 |
| 중계 엣지 캐시 (검색어 → 검색 결과) | Cloudflare 캐시 | 1시간~7일 | 검색어(주제 키워드)와 공개 서지만. 기기 ID·학생 문장은 없음 |

- **호출 제한용 식별:** 중계 함수는 IP 대신 브라우저가 만드는 임의 기기 ID를 쓴다. 학교 망은 한 반이 IP 하나를 공유할 수 있기 때문이다.
- **사용 통계:** P0에서는 수집하지 않는다. 테스트 지표(리서치 시간 등)는 테스트 참가자 기기에서 "기록 내보내기"로 받는다.
- **P1 로그인 도입 시:** 미성년자 개인정보 수집이 시작되므로 개인정보처리방침과 동의 절차를 함께 준비한다. 만 14세 미만은 법정대리인 동의가 필요하다.
